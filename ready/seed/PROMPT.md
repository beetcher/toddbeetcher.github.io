# Builder validation seed generation prompt

Use this prompt with the schema in `../schemas/bulk_import.schema.json`. The file `ai_readiness.json` is a ready-to-validate example; it is not already imported into Firestore.

> Generate JSON only matching the supplied READY bulk-import schema. Set dry_run true. Create ten independent question atoms and four offered answer choices for each of ten authored sets. Use single_choice or multiple_choice, with contextual strong/ambiguous/incorrect roles on set connections, never on answer atoms. Reuse answer atoms when identical wording genuinely fits more than one set. Each set needs at least one strong answer; a single-choice question has exactly one strong answer. Every client_ref is a unique lowercase underscore identifier; references resolve to atoms in this file. Include rich topics, audiences, difficulty, learning_objectives, description and tags. Every question, answer and set has tags builder_created, system_validation and a stable seed batch label. Include true system authorship/source provenance and teaching feedback explaining each choice. Do not invent a human author. No people, tests, attempts, credentials, operational timestamps, UUIDs, live session flow or service scores. Use no unsupported metadata attributes. Content is illustrative test material, not a validated or official certification assessment.

An import dry run validates references/content before commit. Future import service assigns server IDs and maps client refs. The current fixture checker verifies structure only; service-level import and cross-record tests must precede a live commit.
